2. Popover/TopProcessesView.swift
固定十个物理 row 会按排名重新绑定 process。selection 本已按完整进程身份跟随，但 window.firstResponder 留在旧物理 row/button，排序后空格/按钮操作会指向另一个进程。真实 GUI 基线已复现，未调用真实终止。
最小修复在更新内容 guard 后、重绑前捕获属于本列表的 focused row/button 与其 Selection(process)；重绑完成后按身份找可见新 row：若原来是 action 且该 row 仍选中且 button enabled，则聚焦其 button，否则聚焦该 row。进程离开列表则 makeFirstResponder(nil)。外部 responder（包括 NSTextView field editor）不捕获、不更改。没有 selection 规则或布局改变。
    let focusedRow = rows.first { $0 === window?.firstResponder || $0.forceQuitButton === window?.firstResponder }
    let focusedProcess = focusedRow?.process.map(Selection.init)
    let focusedAction = focusedRow != nil && focusedRow?.forceQuitButton === window?.firstResponder
    // Existing state/row update unchanged.
    if let focusedProcess, let window {
        if let row = rows.first(where: { !$0.isHidden && $0.process.map(Selection.init) == focusedProcess }) {
            let target: NSView = focusedAction && row.isSelected && row.forceQuitButton.isEnabled
                ? row.forceQuitButton : row
            if window.firstResponder !== target { window.makeFirstResponder(target) }
        } else {
            window.makeFirstResponder(nil)
        }
    }

3. Helper/wattson-helper.swift
socketPollTimeoutMilliseconds 原来无 reader 时使用 absolute idle uptime deadline。worker pending 会阻止 idle exit；若它被阻塞超过 12 秒，idle deadline 已过，poll(timeout:0) 会反复空转。人为阻塞现有采样锁的受控夹具已复现，不能据此声称正常使用有性能退化。
函数新增 backgroundWorkPending: Bool，优先保留 nextReadContinuousDeadline；只有没有 reader、idle deadline 已到且后台 worker pending 时返回 100 ms。main loop 传入 thread-safe topProcessesWorker.hasPending。完成后的退出 predicate、12 秒生命周期、两个时钟域与 reader round-up/clamp 均不变。新连接仍可立即唤醒 poll。
53 项 helper contract 通过，新的 executable regression 在旧 body 明确运行时失败，在修复后通过。夹具每约 303 ms 的 poll 次数从数万降为 3 次；只是异常边界的对照。
