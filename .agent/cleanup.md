# Project memory: automatic build and test cleanup

Standing user requirement, reaffirmed 2026-10-26: every build and test must
clean its disposable resources when that invocation ends. Old app versions and
test preferences must not accumulate. Manual removal or a passing rerun is not
a substitute for fixing the lifecycle that left them behind.

## Required entrypoints

- Swift tests, including filters and `--skip-build`: `bash scripts/test_swift.sh`.
  Create suites with `testDefaultsSuite`, or register an injected unique suite
  with `registerTestDefaultsSuite`, before constructing UserDefaults.
- Python tests: `python3 -m unittest discover -s tests -v`. Runtime fixtures
  must use `tests/local_runtime.py`; allow `cleanup_grace=65` when it wraps a
  lifecycle shell script. Keep real GUI interaction opt-in.
- Renderer benchmark: `bash scripts/measure_renderers.sh --compile-only` by
  default. Use `--run-gui` only in a disposable logged-in GUI VM.
- Release packaging: `bash scripts/release.sh` owns the build, package and
  verification lifecycle. Follow `release.md` for final artifacts and explicit
  handoffs. Other build/preview scripts must retain their shared cleanup hooks.

SwiftPM's incremental compiler cache is reusable build state. Disposable app
bundles, preference domains, test containers, processes and mounts are not.

## Ownership and acceptance

Use `scripts/lib/local_cleanup.sh` for shell lifecycles. Register resources
before use and keep scratch in unique project-local `.noindex` directories.
The owner must stop its process group before clearing its exact preference
domains, unregister apps before removing them, detach mounts before removing
their directories, and remove only containers created by that invocation.
Apply the same cleanup on success, failure, timeout and catchable HUP/INT/TERM.
Report cleanup failures as failures; do not silently turn them into success.

Verify cleanup after the owner exits, against the real user's Preferences
directory and this run's registered domains. For a full Swift run, confirm the
log reports `registered > 0` and `remaining=0`. Check disposable scratch is gone.
When app bundles were used, also check their LaunchServices/Spotlight entries.
Never sweep another run's domains or delete the canonical installation,
production user data, explicit caller-owned inputs or final distribution files.
Retained review artifacts must have an explicit owner and purpose.

When changing a lifecycle, exercise failure, timeout and catchable interruption
as well as successful exit. A parent killed with SIGKILL or a power loss cannot
run exit cleanup; inspect the identifiable owned resources before declaring
such an interrupted run clean.

## Root cause to remember

The 180 empty Swift test preference files found in October 2026 exposed two
gaps: `CFFIXED_USER_HOME` redirected Foundation's home lookup while cfprefsd
still wrote into the account's real home, and the parent audited only its own
suite rather than the suites generated by individual Swift tests. Unsetting
the variable and rerunning did not clean the earlier run's files.

The fix uses the real account home, registers every suite before writing, and
cleans from the parent after the test process stops. Do not bypass that owner
or treat `CFFIXED_USER_HOME` alone as preference isolation. See the
[root-cause and verification record](../design/preferences-cleanup-20261026/README.md)
and [debugging guide](debugging.md) for implementation details.
